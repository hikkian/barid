# Обещание совместимости (1.0)

[English](COMPATIBILITY.md) · [Қазақша](COMPATIBILITY.kk.md)

Начиная с 1.0 скрипты, подсказки для агентов и доски, написанные под один выпуск 1.x, продолжают работать со всеми следующими выпусками 1.x. `tests/test_contract.py` проверяет список ниже при каждом изменении; если приходится менять один из этих тестов, это уже 2.0.

## Что заморожено

- **Файл доски.** Схема `1` (`"schema": 1`). Статусы (`draft`, `proposed`, `queued`, `sent`, `running`, `review`, `done`, `cancelled`), исходы (`complete`, `partial`, `failed`), поля доски и задачи по списку в тесте и их смысл. Читающая программа может игнорировать незнакомое поле; Barid сохраняет незнакомые поля при записи.
- **Доски всех выпусков открываются.** Доска, созданная версией 0.1 или любой следующей, открывается, планируется, экспортируется и принимает новые задачи в текущей версии; чтение никогда не переписывает файл (`tests/fixtures`, `tests/test_migration.py`).
- **Коды выхода.** `next`: `0` задача выведена, `2` в дорожке ничего нет в очереди, `3` пока ничего нельзя начать, но начнётся само, `4` нужен человек. `claim`: `0` взято, `3` надо ждать (время начала, другие задачи, конфликт), `4` нужен человек. Любая другая ошибка даёт `1`.
- **Коды причин ожидания:** `begin_time`, `dependency`, `conflict` (проходят сами), `decision`, `never` (нужен человек). У причины могут быть дополнительные поля (`via`, `stale`); пять кодов остаются.
- **Имена команд и их флаги.** В 1.x команду или флаг не удаляют и не переименовывают. Новая команда или флаг могут появиться.
- **Вывод `--json`.** Каждое поле, которое есть сейчас, остаётся со своим смыслом; новые поля могут добавляться.
- **Протокол агента.** `connect` → `next` → `claim` → работа → `finish` с `--report`, `--outcome`, `--by` и коды выхода выше. Сессия, которая следует выведенному тексту, продолжает работать после обновления.

## Что может меняться

- Формулировки текстов для человека (сообщения, текст подключения, нижняя часть подсказки): их не нужно разбирать программой, в скриптах читайте коды выхода и `--json`.
- Внешний вид панели, её переводы и устройство логов в `runs/`.
- Новые команды, флаги, поля и подробности причин.
- Внутренние функции `barid.py`: это программа, а не библиотека.

## Если что-то придётся убрать

Команда или поле, которые надо убрать, сначала помечаются устаревшими с предупреждением минимум на один минорный выпуск, а удаляются только в 2.0 вместе с описанием миграции в списке изменений. Изменение схемы доски сопровождается автоматическим чтением старой схемы.

## Какие файлы пишет Barid

`board.json` (записывается атомарно и сбрасывается на диск), `board.json.bak` (версия до последнего изменения, жёсткая ссылка: лишние данные не пишутся), `board.json.lock`, временные `board.json.tmp*` (удаляются, когда стареют) и `runs/` (журналы `barid worker`). Переменные окружения: `BARID_BOARD`, `BARID_AGENT`, `BARID_ACTOR` (`human`: действовать как человек) и `BARID_LOCK_WAIT` (сколько секунд команда ждёт блокировку доски, по умолчанию 60) стабильны; `BARID_WORKER_BACKOFF` существует только для тестов.
