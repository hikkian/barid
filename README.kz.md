**Бірнеше AI agent сессиясын қатар жүргізетіндерге арналған промпт тақтасы.**
Жоспарлаушы агент промптты жазады, сіз оларды басқа сессияларға көшіріп саласыз, ал тақта ретті, кім неге тәуелді екенін, нені қатар орындауға болатынын және не қақтығысуы мүмкін екенін бақылап отырады: ортақ GPU немесе сынақ сервері, бірдей файлдар немесе бір сессия. Ол **agent skill** (агентіңіз тақтаны сіздің орныңызға жүргізе алады) және шағын **браузер панелі** (көріп, басып басқаруыңызға) түрінде жеткізіледі.

![Barid in action](docs/img/demo.gif)

- **«Келесі қай промпт?» деген сұрақ жоқ.** Панель қазір нені жіберу керегін, қай тапсырмаларды қатар орындауға болатынын және қайсысы күтуі керегін көрсетеді («T1 тоқтатып тұр: GPU», «файлдар ортақ: src/api»).
- **Агенттер тақтаны өздері басқарады.** Skill-ді орнатыңыз; агентіңіз тапсырма қосады, жетіспейтін промптты жазады, есептерді тіркейді. Басқа сессиялар өз тапсырмасын иемденіп (claim), есеппен аяқтайды.
- **Құрылымынан қауіпсіз.** Эксклюзивті ресурстар (GPU, сынақ сервері, «пайдаланушы бар») жалға беріледі (lease), ал git тексеруі бар файл аймақтары бірдей файлдарды өңдеп жатқан сессияларды анықтайды, сондықтан сессиялар бір-біріне кедергі келтірмейді. Агент қосқан тапсырмалар сіздің бекітуіңізді күтеді. Ештеңе жойылмайды, тек бас тартылады (cancelled). Әрбір өзгеріс журналға жазылады.
- **Тәуелділіксіз, шағын, жергілікті.** Бір Python файлы (3.9+), бір JSON файлы, сұраныс бойынша іске қосылатын және бос тұрса өшетін жергілікті панель. Аккаунт жоқ, бұлт жоқ, телеметрия жоқ.

## 60 секундта бастау

```bash
git clone https://github.com/hikkian/barid
cd your-project
python3 /path/to/barid/skills/barid/scripts/barid.py init --lanes planner,worker-a,worker-b
python3 /path/to/barid/skills/barid/scripts/barid.py shim      # optional: installs a short `barid`
barid open                                                              # the panel
```

Немесе алдымен мысал тақтаны қарап көріңіз:

```bash
python3 examples/build_example.py /tmp/barid-demo
cd /tmp/barid-demo && python3 /path/to/barid/skills/barid/scripts/barid.py open
```

## Оны AI агентіңізге орнату

Skill — қарапайым [Agent Skill](https://docs.claude.com/en/docs/claude-code/skills) қалтасы (`skills/barid/`: `SKILL.md`, `barid.py` скрипті, панель және промпт шаблондары). Сол қалтаны агентіңіз skill іздейтін жерге қойыңыз:

| Агент | Қайда |
|---|---|
| Claude Code (plugin) | `/plugin marketplace add hikkian/barid`, содан кейін `/plugin install barid@barid` (немесе shell-де `claude plugin marketplace add hikkian/barid`) |
| Claude Code (қолмен) | `skills/barid` қалтасын `~/.claude/skills/barid` (барлық жобаларға) немесе `.claude/skills/barid` (бір жобаға) жолына көшіріңіз |
| Codex CLI | оны `~/.codex/skills/barid` жолына көшіріңіз (Windows: `%USERPROFILE%\.codex\skills\barid`) |
| OpenCode және оның fork-тары | оны `~/.config/opencode/skills/barid` жолына көшіріңіз; OpenCode сонымен бірге `~/.claude/skills` және `~/.agents/skills` қалталарын да оқиды |
| Басқа кез келген агент | [docs/AGENT.md](docs/AGENT.md) мазмұнын агентке қойыңыз немесе төмендегі бір жолдық нұсқауды оның `AGENTS.md` файлына қосыңыз |

Жолдар әр құралдың 2026 жылғы қазандағы құжаттамасына сай ([Claude Code](https://code.claude.com/docs/en/skills), [Codex](https://developers.openai.com/codex/skills), [OpenCode](https://opencode.ai/docs/skills)); skill табу тәртібі уақыт өте өзгереді, сондықтан skill көрінбесе, өз құралыңыздың құжаттамасын тексеріңіз. Skill-ге Python 3-тен басқа ештеңе керек емес. Plugin және marketplace манифестері `claude plugin validate` тексеруінен өтеді.

Содан кейін агентіңізбен жай сөйлесіңіз:

> "Set up a Barid for this project. I run three sessions: a planner, a builder and a tester."
> "Add a task for the tester: run the regression suite on the new build. It needs the builder's task first."
> "What can I run right now? Which of those can run in parallel?"
> "Write the prompt for T4 now that T3 is done."

Skill-дері жоқ агенттер үшін мынаны `AGENTS.md` файлына жазыңыз:

```
This project uses Barid. Before planning work for other sessions, read docs/AGENT.md of
https://github.com/hikkian/barid and use `python3 <path>/barid.py` as described there.
```

## Қалай жұмыс істейді

```
        you                         planner agent                  worker sessions
         |  barid open (panel)              |  barid add / barid edit              |  barid next / claim / finish
         v                               v                                v
   +----------------------------------------------------------------------------+
   |   .barid/board.json   (one file, locked + atomic writes, event log)    |
   +----------------------------------------------------------------------------+
```

- **Lane-дер** — сіздің сессияларыңыз. Бір lane бір уақытта бір тапсырманы орындайды. Жаңа сессияны панельдегі «+» батырмасымен немесе `barid lane add` командасымен қосады; *Қосу* батырмасы (немесе `barid connect LANE`) сол агент терезесіне бірінші хабарлама ретінде қоятын мәтінді береді, содан кейін агент тапсырмаларды тақтадан өзі алады.
- **Тапсырмаларда** промпт, тәуелділіктер (`--needs`), эксклюзивті ресурстар (`--uses gpu`) және екі жалауша бар: `--quiet` (машина тыныш болуы керек) және `--noisy` (CPU-ны немесе десктопты жүктейді). Тақта осылардан қайсысы *ready* (дайын), *waiting* (күтуде) немесе *blocked* (бөгелген) екенін есептейді және *қадамдарды* жоспарлайды: бір қадамдағы тапсырмаларды бір мезгілде орындауға болады.
- **Промпттар өз нұсқауларын өздері алып жүреді.** *Промптты көшіру* батырмасын басқанда тақта промптқа нақты командалары (`claim`, `finish`, `note`) және `barid.py` жолы бар қысқа төменгі жазба қосады, сондықтан skill-i жоқ сессия да есепті қалай тапсыру керегін біледі.
- **Draft тапсырмаларда** тек жоспар-сипаттама болады. Кезегі келгенде панель *Промпт жасату* ұсынады: ол агентіңізге арналған сұранысты көшіреді (сипаттама, аяқталған тәуелділіктердің есептері, контекст файлдары, промпт қаңқасы), агент промптты жазып, `barid edit` арқылы сақтайды.
- **Есептер** тексеру кіріс жәшігіне (inbox) түседі. *Есепті қабылдау* тәуелді тапсырмаларды ашады (немесе есеп жазылысымен-ақ ашылады; мұны саясат ауыстырғышы белгілейді).

```
draft -> queued -> sent -> running -> review -> done        (proposed -> queued on approval; cancelled anywhere before done)
```

## Бір жобадағы екі (немесе одан да көп) түрлі агент

Barid сессияның артында қай агент тұрғанына мән бермейді: Claude Code және Codex, Claude Code және жергілікті модель, үш Codex терезесі. Әрқайсысына өз lane-ін беріп, қай агент екенін көрсетіңіз:

```bash
barid init --lanes "claude:Claude Code,codex:Codex,local:Local model"
barid lane edit claude --agent claude --color "#ff8fb3" --human
barid lane edit local  --agent local  --color "#86f9e4" --human
```

Оларды команда етіп жұмыс істететін нәрселер:
- **Табыстау (handoff).** Тапсырма аяқталғанда, оған тәуелді әрбір тапсырманың промпты автоматты түрде қысқа табыстаудан басталады: оны кім орындады (lane және агент), нәтиже, есептің жолы, branch және worktree, қанша файл өзгергені және қайсысы, соңғы жазбалар. Жұмысты жалғастыратын агентке сіз ештеңені қайта айтып беруіңіз қажет емес.
- **Бәріне бірдей ережелер.** Промптта иемдену және аяқтау командалары, файл аймағы және қорғалған жолдар бар, сондықтан агент `CLAUDE.md` немесе `AGENTS.md` файлын оқи ма, әлде екеуін де оқымай ма, бәрібір.
- **Шағын модельдерге кеңес.** Агенті `local` болатын lane қосымша бір жол алады: қадамдарды бір-бірлеп орындаңыз, командаларды жазылғанындай іске қосыңыз, қадам түсініксіз болса, соны айтыңыз.
- **Қақтығыстар жоқ.** Эксклюзивті ресурстар, файл аймақтары және бөлек worktree-лер агенттер арасында да бірдей жұмыс істейді (жоғарыны қараңыз).

## Бұл басқалардан несімен ерекшеленеді?

Бірнеше агентпен жұмысқа көмектесетін құралдар бұрыннан бар. Barid — басқа ұстанымы бар шағын құрал, сондықтан міне адал карта (2026 жылғы қазандағы жағдай бойынша; олардың беттерін тексеріп отырыңыз, олар жылдам өзгереді):

| | Негізгі міндеті | Barid-тен айырмашылығы |
|---|---|---|
| [Claude Squad](https://github.com/smtg-ai/claude-squad) | Бірнеше агентті, әрқайсысын өз git worktree-інде іске қосатын терминал UI | Ол сессияларды іске қосып, өзі ұстайды; Barid ештеңе іске қоспайды, жұмысты жоспарлап, промпттарды сізге береді |
| [Vibe Kanban](https://github.com/BloopAI/vibe-kanban) | Карточкалардағы тапсырмаларға кодтау агенттерін қосып, нәтижелерін тексеретін kanban қолданбасы | Ол агенттерді өзі басқарады; Barid-пен сіз ортада боласыз және өзіңізде бар терезелерді қолданасыз |
| [MCP Agent Mail](https://github.com/Dicklesworthstone/mcp_agent_mail) | Агенттер арасындағы хабар алмасу: тұлғалар, кіріс жәшіктері және кеңес беретін файл жалдары | Агенттер бір-бірімен MCP сервері арқылы сөйлеседі; Barid-те агенттен агентке чат жоқ және MCP қажет емес |
| [Aqua](https://github.com/vignesh07/aqua) | CLI агенттері үшін атомарлы иемденуі және файл құлыптауы бар ортақ тапсырма кезегі | Рухы жағынан ең жақыны. Aqua агенттерге кезектен тапсырма таңдауға мүмкіндік береді; Barid қосымша промпт мәтінін сақтайды, ретті және қатар қадамдарды жоспарлайды, адал нәтижені жазып алады |
| Claude Code agent teams | Claude Code ішінде әріптес агенттерді туғызып, басқаратын жетекші агент | Бір өнімнің ішінде жұмыс істейді; Barid өнімдер арасында жұмыс істейді (Claude Code, Codex, OpenCode, жергілікті модель) |

Barid не қосады, әрқайсысы бір жолмен:

- **Жұмыс бірлігі — промпт.** Тақта сіз қоятын мәтінді сақтайды, жоспарлаушы промптты жазғанша тапсырманы draft күйінде ұстай алады және аяқталған тапсырманың нәтижесін келесісіне табыстайды.
- **Процесте әдейі өзіңіз қаласыз.** Ештеңе іске қосылмайды және басқарылмайды. Команда орындай алатын кез келген чат терезесі немесе терминал жарайды, ал агент тек өз тапсырмасын ұсына, иемдене және аяқтай алады.
- **Адал аяқталу.** Тоқтатылған, жартылай немесе сәтсіз орындалу оған тәуелді тапсырмаларды өздігінен ешқашан ашпайды; шешімді сіз қабылдайсыз.
- **Бір файл, daemon жоқ.** Тек Python, JSON тақта, қосымша панель. MCP сервері жоқ, дерекқор жоқ, API кілттері жоқ.

Кімге арналмаған: агенттер қадағалаусыз жұмыс істесін, мақсатты өздері ішкі тапсырмаларға бөлсін және branch-терді біріктірсін десеңіз, кестедегі оркестраторды қолданыңыз. Barid рульді өз қолында ұстағанды жөн көретіндерге арналған.

## Сессияларды бір-біріне кедергі келтірмеуден сақтау

Екі сессия тек GPU үшін сирек таласады: олар бір-бірінің файлдарын да үстінен жазып жібереді. Barid мұны төрт деңгейде шешеді:

1. **Эксклюзивті ресурстар** (`--uses gpu`): бір уақытта тек бір тапсырма (жоғарыдағыдай).
2. **Файл аймақтары** (`--touches src/gateway,tests`): тапсырма өзгерте алатын файлдар, қалталар немесе glob-дар. Аймақтары қиылысатын тапсырмалар ешқашан қатар орындалмайды, ал панель себебін айтады («T1 күтілуде, файлдар ортақ: src/gateway.py»). Қиылысу тексерісі сақ жүреді: шын мәнінде қақтығыспайтын екі тапсырманы да бөгеп тастауы мүмкін, бірақ керісінше ешқашан болмайды.
3. **Қорғалған жолдар** (`barid protect add config/live.json`): ешбір тапсырма өзгертпеуге тиіс файлдар. Barid тапсырма иемденілгенде бақылау қосындысын (checksum) алады да, тапсырма аяқталғанда салыстырады.
4. **Оқшауланған checkout-тар** (`barid worktree T1`): тапсырмаға арналған жеке git worktree және branch, ол промптқа жазылады («тек ... ішінде жұмыс істе»). Әртүрлі worktree-лердегі тапсырмалар бір-бірінің үстінен жаза алмайды, олардың жұмысы біріктіру кезінде кездеседі.

Тапсырма аяқталғанда Barid git-тен иемденуден бері не өзгергенін де сұрап, **тапсырма аймағынан тыс** кез келген нәрсені, **басқа орындалып жатқан тапсырманың аймағындағы** кез келген нәрсені және өзгерген кез келген **қорғалған файлды** белгілейді. Мұндай белгілері бар есеп, тіпті *complete* десе де, тәуелді тапсырмаларды өздігінен ешқашан ашпайды: ол файлдар тізімімен бірге сіздің inbox-ыңызда күтеді. `barid check T1` бастамас бұрын не қақтығысуы мүмкін екенін көрсетеді.

Бұл **сандбокс емес, анықтау мен келісім**: агент өзіне жазуға рұқсат етілген кез келген файлды әлі де жаза алады. Промпт оған ережелерді айтады, worktree оның өзгерістерін бөлек ұстайды, ал Barid бұзушылықтарды байқамай қалу мүмкін емес етеді. Қатаң кепілдіктер үшін оны ОЖ деңгейіндегі рұқсаттармен немесе контейнерлермен біріктіріңіз.

|---|---|
| **Қазір не істеу керек** | әр lane бойынша: орындалып жатқан тапсырма немесе *Промптты көшіру*, *Жіберілді деп белгілеу* және *Қосу* батырмалары бар келесі дайын тапсырма; таңдалған тапсырмаларды қатар орындауға бола ма, соны айтатын жол |
| **Inbox** | агенттердің ұсыныстары (*Мақұлдау / Өзгерту / Қабылдамау*) және тексеруге арналған есептер (*Қабылдау / Қайта жұмысқа қайтару*) |
| **Order** | параллель топтары бар қадамдар, тәуелділік чиптері, ресурс тегтері, нәрсенің неге бөгелгені |
| **Details** | промпт мәтіні, жазбалар, тарих, өңдеу формасы, кез келген күй |
| **Archive / Activity** | аяқталған және бас тартылған тапсырмалар, оқиғалар журналы |

Ағылшын, орыс және қазақ тілдері кіріктірілген (автоматты анықталады, тілдер тізімінен тақырыпта таңдалады; Barid агенттеріңізге жазатын мәтіндердің өз тілі бар: ол тақта жасалғанда жүйе тілінен алынады, оны `barid lang en|ru|kk` командасымен таңдайды), ашық, күңгірт немесе автоматты режим және төрт түс палитрасы (Forest, Teal, Graphite, Midnight) *Көрініс* батырмасынан, телефонда да жұмыс істейді. Дәл сол мәзірден **әр сессияға ат пен түс беруге** және онда қай **агент** жұмыс істейтінін көрсетуге болады (Claude Code, Codex, OpenCode, Gemini CLI, Cursor, Aider, жергілікті модель немесе кез келген атау); агент сессияда белгі (badge) ретінде көрінеді. Панель тек беті көрініп тұрғанда сұраныс жібереді және жабық кезде ештеңеге жұмсалмайды: сервер 30 минут бос тұрса өшеді (`barid open --idle-exit 0` оны қосулы ұстайды).

## Командалық жол

Әрбір команда `--json` қабылдайды. `barid --help` барлығын тізіп береді.

```bash
barid init --lanes main,helper               # create .barid/board.json here
barid add T1 --lane main --title "Build" --text-file p.md --uses gpu --by planner
barid add T2 --lane helper --title "Analyse" --outline "summarise T1's results" --needs T1 --by planner
barid plan                                   # steps and what can run together
barid next --lane helper                     # the next ready prompt for a lane (exit code 2 if none)
barid claim T1 --by worker-a                 # refused when a conflicting task is running
barid finish T1 --report reports/t1.md --by worker-a
barid gen T2                                 # request that makes an agent write T2's prompt
barid move T3 1                              # priority: earlier in the list = earlier slot in the plan
barid add T3 --lane a --touches src/api --text-file p.md   # file scope: overlapping scopes never run together
barid protect add config/live.json        # no task may change it (verified at finish)
barid worktree T3                         # an isolated git worktree and branch for the task
barid check T3                            # what could collide with it
barid lane edit a --title Builder --color "#7c5cff" --agent codex   # name, colour and agent of a session
barid lane add tests --title Tests --agent codex       # a new session (or the "+" button in the panel)
barid connect tests                          # the first message to paste into that agent's window
barid open                                   # panel;  barid export board.html  = read-only snapshot
```

Тек адам орындайтын әрекеттер (`approve`, `accept`, `sent`, `status`, `restore`, `purge`, `trust`) үшін `--human` (немесе `BARID_ACTOR=human`) керек; панель оларды сіздің орныңызға орындайды. Барлық ережелер мен файл форматы үшін [docs/PROTOCOL.md](docs/PROTOCOL.md) қараңыз.

## Қауіпсіздік моделі

Barid кездейсоқ қателерден сақтайды, зиянды әрекеттен емес. Тұлғалар өздігінен жарияланады (`--by`), сондықтан компьютеріңізде `barid` іске қоса алатын кез келген процесс өзін сіз деп атай алады. Ол нені кепілдейді:

- барлық жазулар атомарлы және файл құлпы арқылы реттелген; бір GPU үшін таласқан екі агент екеуі де жеңе алмайды (thread және процестермен тексерілген);
- агенттер бекіте, қабылдай, еркін күй орната, purge жасай алмайды және басқа агент ұстап тұрған тапсырманы аяқтай алмайды;
- тапсырманың жарияланған аймағынан тыс, басқа орындалып жатқан тапсырма аймағындағы немесе қорғалған жолдардағы файл өзгерістері тапсырма соңында анықталады және сіз шешім қабылдағанша тәуелді тапсырмаларды бөгеп ұстайды;
- агенттер тапсырмаларды ешқашан жоймайды, тек бас тартады (cancel); оқиғалар журналы тек толықтырылады (append-only);
- панель сервері тек loopback-ке байланады, бөгде `Host` және `Origin` тақырыптарын қабылдамайды және тек бір қорғалған эндпойнт арқылы жазады (арнайы тақырып, сондықтан басқа сайт оған post жібере алмайды);
- панель тапсырмаларда аталған файлдарды ешқашан оқымайды (есеп жолдары көрсетіледі, бірақ ашылмайды).

Құпияларды промпттар мен жазбалардан тыс ұстаңыз: тақта — жоба қалтаңыздағы қарапайым JSON (оны коммитке қосқыңыз келмесе, `.barid/` жолын `.gitignore` файлына қосыңыз).

## Мәртебесі

Мен Barid-ті өзіме жасадым, өз агент терезелерімнің есебін жоғалтпау үшін. Сізге пайдалы болса, қолдана беріңіз; идеялар мен қате туралы хабарламалар қуана қабылданады, бірақ бұл бір адамның жобасы және жылдам жауап беруге уәде бере алмаймын.

0.4 нұсқасы, авторы күн сайын екі агент сессиясын жүргізу үшін қолданады. Linux — сыналған негізгі орта; macOS және Windows CI-мен қамтылған, бірақ нақты өмірде аз қолданылған, ал мұнда ештеңе AMD немесе Intel GPU-да сынақтан өткен жоқ (Barid-тің өзі GPU-ға мән бермейді: ол тек ортақ ресурсты кім ұстап тұрғанын бақылайды). `barid doctor` шығысы бар қате туралы хабарламалар өте қош.

## Талаптар және платформалар

Python 3.9 немесе жаңарақ, кез келген ОЖ. CI тесттерді Linux, macOS және Windows-та іске қосады. Панельге кез келген заманауи браузер жеткілікті. Оны әрқашан үстіңгі терезе ретінде ұстағыңыз келсе, оны қолданба терезесінде (`chromium --app=URL`) ашып, терезе менеджеріңізбен бекітіңіз.

## Атауы

*Barid* (بريد) — арабша «пошта» деген сөз. Ол сондай-ақ алғашқы халифаттардың эстафеталық пошта қызметінің атауы болған: курьерлер хабарларды бекеттер тізбегі бойымен бекеттен бекетке тапсырып отырған. Промпттар — хабарлар, агент сессияларыңыз — бекеттер, ал бұл — эстафетаны реттеп тұратын тақта. (Алғашқы жұмыс атауы RelayBoard болған; ескі `rb`, `RB_*` және `.relayboard` атаулары әлі де жұмыс істейді.)
